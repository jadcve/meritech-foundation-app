# Testing

## Objetivo

Las pruebas deben proteger contratos, flujos base y reglas transversales sin convertir Foundation en un producto final.

## Criterios

- Probar Core por contratos y comportamiento observable.
- Probar modulos futuros de forma aislada.
- Evitar fixtures con vocabulario de negocio especifico.
- Mantener pruebas de integracion para flujos Laravel existentes.

## Pendiente

La estrategia detallada de pruebas por modulo debe documentarse antes de implementar nuevos modulos.
